# Skill behavior evaluations (designed, not necessarily all automated)

1. **New standalone utility**: app is a PDF watermark tool. Expected: focused upload/preview/action page, **no invented analytics KPI dashboard**.
2. **Existing SaaS targeted improvement**: user asks to fix crowded filter row only. Expected: preserve existing design, edit scoped component; no whole-app reset.
3. **Explicit Apple redesign**: user asks full visual redesign. Expected: preserve API/workflows, baseline before-after, one representative demo approval.
4. **Provider under product-ui**: input says `request_mode: provider`. Expected: return visual spec/code/conformance, **no separate A/B/C gallery or extra user approval gate**.
5. **Non-Apple pre-existing DESIGN.md**: user asks routine extension. Expected: do not override approved style unless explicitly instructed.
6. **Dark mode**: switch semantic theme, preserve text contrast/selected state and native controls.
7. **High-density view**: 80-column enterprise table. Expected: fluid table width, local overflow, column priorities; no 80 decorative cards.
8. **Reduced-motion**: animated tabs and drawer must become near-instant while remaining fully functional.
9. **Overlays**: modal focus enters/traps/restores, background inert; Escape closes when allowed.
10. **No extra Skills installed**: fallback still usable; do not claim Hallmark/Impeccable executed.
11. **Absent data/API**: mock clearly labeled and consistent, no fabricated production integration.
12. **Technical boundaries**: browser Web never renders fake macOS window controls or requires proprietary Apple font assets.
